**Required: public value hashes can be reversed for low-entropy Kobo fields**
`structural()` publishes plain SHA-256 hashes of individual changed leaves (diagnostic_compare.py:27 and :45). On any UNEXPLAINED path that changes a scalar, that hash is effectively the raw value. One realistic case is an existing conflict revised in place (koboController.js:976-1013), which you deliberately leave UNEXPLAINED. I ran that through `classify_sample` and the public output contained `value_hash(14.634915)`, `value_hash(14.634999)` and `value_hash(-90.506777)`, the old and new lat/lng. Brute-forcing one coordinate is cheap, and the same goes for `collected_at`, `site_id` or a surveyor name. Fix options:
- Preferred: compute every public per-value hash as HMAC-SHA256 with a fresh 32-byte `os.urandom` key made at run start and kept only in a withheld `private-*.json` (0400). Tests use a fixed key. Whole-table stream hashes can stay plain.
