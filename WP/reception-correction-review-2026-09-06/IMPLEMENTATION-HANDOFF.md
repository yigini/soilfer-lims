## 1. Close the draft lifecycle bypass first

`server/controllers/receptionController.js` currently applies its locked-status guard only when `!req.body.isDraft`, then writes `status:'DRAFT'` directly. Enforce permitted draft/intake edits on the server for every command, using the current persisted state, scope and revision. Approved, submitted, processing, archived and other locked states must not regress through draft save. Revisions of already received records must follow the authorized intake correction policy and retain custody/history. Check transitions atomically so another user accepting the sample while a draft is open cannot be bypassed.

Preserve existing project origin, identifiers, field metadata and custody. A client mode flag must not convert an existing project sample into a walk-in or clear its project. Prevent direct requests and legacy endpoints from bypassing the same rules. Do not alter any real sample status to demonstrate the fix.

## 2. Load and restore the complete intake context

`client/src/pages/Reception.jsx:handleLookup` uses `/api/samples?originalId=...&limit=1` as a complete record. `server/controllers/sampleController.js:getSamples` intentionally strips field metadata and does not select saved reception details or projectId. Preserve the efficient list response. Resolve the exact sample ID, then load a scoped, read-only intake-detail response before displaying or restoring it. Do not make every sample-list row carry large survey/attachment blobs. The existing full-detail route has legacy self-healing writes; avoid introducing these side effects into reception reads.

Use one coordinate/context resolver for lookup, autocomplete, draft resume, provenance card and map. Handle scalar and `{value,source}` values, existing canonical fields and supported GPS formats; accept valid zero latitude/longitude, reject blank/boolean/non-finite/out-of-range values. Distinguish data not loaded, location unknown, text-only location and recorded coordinates. Do not label coordinates “verified” or “field-grade GPS” merely because a pair exists, or invent depth 0–20 cm when absent.

Restore all saved intake fields, not just the map: explicit origin/project, requested bundle plus additions/removals and their justification, desk facts, notes, photographs, submitter, sampling and custody draft. Persist these deltas on draft save. Reset state between samples; a missing field must not inherit the previous sample's value. Preserve the original field location and provenance unless a separately authorized correction is recorded. Distinguish field sampling location from physical laboratory storage location.

Inspect `LocationPicker.jsx` while repairing this path: its fallback map center is currently shown as a marker/input and copied to `lastIntakeLocation`. A map viewport is not captured sample evidence. Leave coordinates unrecorded until explicit capture/reuse; “Same as previous” must be deliberate and appropriately scoped, not automatic carryover.

## 3. Give reception a coherent dashboard

Replace the reception branch of `/api/dashboard/live` in `server/app.js` with explicitly defined reception metrics and matching scoped drill-downs. Preserve other roles and use shared readiness rules for any operational counts.

Suggested reception layout:

```
Reception                                      [New intake]
Expected arrivals | Incomplete drafts | Received today | Needs attention

Needs attention / Drafts / Expected arrivals / Recent receipts
Sample | Project or client | Intake state | Missing information | Next action

Optional: laboratory handoff overview (separate from today's activity)
```

Default to actionable work, not a misleading empty tab. Expected arrivals and drafts must never appear as drying/preparation work. If handoff counts are retained, require actual receipt and active operational tasks, apply relevant readiness/hold rules, exclude terminal/superseded/not-required tasks, count unique samples consistently, and distinguish waiting for drying from ready for preparation. Do not show the same sample as ready for sequential incompatible stages.

The current `ReceptionDashboard.jsx` funnel mixes `receivedToday` with all-time pending flags and an arrow as the analysis count. Remove it or replace it with comparable, explicitly defined queue counts. Label all registered samples honestly if that statistic remains. Define “today” in the laboratory timezone with a half-open day interval, and label whether records are this officer's or the lab's. Preserve scoped permissions on card links. Show actual loading/error/stale states; do not turn an API failure into healthy-looking zeros. Refresh on relevant intake/sample events as well as work-item events. Localize reception labels consistently with the selected language.

## 4. Remove duplicate quick-intake navigation, preserve valid origins

The sidebar in `client/src/App.jsx` and the dashboard in `ReceptionDashboard.jsx` expose a separate “Quick Walk-in Entry” link to `/reception?mode=WALK_IN`. It is another mode of the same Reception component and same intake endpoint, not an independent backend.

Use one Reception navigation item and one primary New intake action. Within the main console retain Project sample, External/walk-in sample, and Consignment/batch as explicit origins using shared validation, drafts, catalogue and custody rules. Remove the duplicate standalone quick shortcut. Existing walk-in records/drafts and legacy deep links must remain usable through the canonical flow; do not delete data or silently recategorize a project sample. This simplifies navigation without removing laboratories' ability to receive external samples. Avoid a broad unrelated redesign.
