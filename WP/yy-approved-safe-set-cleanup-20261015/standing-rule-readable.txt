**Proposed standing host-capacity rule.** It is not active yet. It takes effect only after YY explicitly approves it, and I will relay that approval here. Until then, each removal still needs its own approved list, as in 6189633644.

The disk keeps filling because closed proof runs leave full working copies of the production DB and assets on the host. Each run needs about 32 GB, and those copies, old images and the build cache are never retired. The rule makes cleanup routine and bounded.

**R1. Cleanup after each proof.** For a run folder under `/opt/lims/releases` that is CLOSED (passed or failed), Pip may remove that folder's derived working copies: DB/WAL/SHM copies and copied asset trees. All of these must hold:
- The run's evidence (receipts, logs, hash records) is committed in Git, and every retained small file is hash-matched to its Git blob.
- Each file to be removed has its SHA-256 and byte length recorded in that published evidence.
- No container mount, no process with the file open, and no open or next run, current release or rollback kit references the folder.
- The folder is not the latest passing proof of the current candidate. That one stays until the post-deploy check for that release passes.

The small evidence files stay. A file whose bytes are not recorded in published evidence stays.

**R2. Build cache.** After each successful build, cap the BuildKit cache at 5 GB with the builder's keep-storage option. Records that are in use or shared with images are never removed. There is no daemon configuration change and no Docker restart.

**R3. Images: listing only.** Always kept:
- the running production image and the one before it;
- the current candidate or qualified image;
- any image referenced by a container (running or stopped), a Compose file, an env file or a retained release;
- every non-LIMS image.

Once a month, Pip lists any other LIMS image on #162, with its size and references. Nothing is removed without YY's approval of that exact list.

**R4. Space check before each proof or build.** Measure free space against that run's computed requirement plus 10 GB of headroom. If space is short, do not start: post the numbers here, and the R1 cleanup that would cover the gap.

**R5. Backups.** No change yet. Off-host copies need a destination YY chooses. No backup is removed under this rule.

**Never under this rule:**
- the production DB, any backup, or analytical, QC or audit data of record;
- any file without a verified copy elsewhere (for example the 050000 raw files and the 060000 DB files);
- a blanket `prune`.

**Receipt for every R1 or R2 cleanup.** A receipt on #162 listing each item with its path or ID, bytes, SHA-256 where it has one, and the reference checks, plus `df` before and after. I check each receipt against this rule in my hourly audit, and report any breach to YY.
