# Project management audit

## Method and severity

Baseline and live-review limitations are in README. **R** = reproduced with isolated fixtures, **L** = observed on live UI, **S** = confirmed source behavior, **V** = downstream risk requiring integration verification. P0 blocks release because of access or data-integrity risk; P1 is required in this project-management release; P2 is usability hardening. These labels do not assert that every local defect is deployed.

## Reproduction summary

The checked-in JSON is the detailed evidence. Fourteen cases exercised the real project router/session/role middleware or its membership service against a new schema-only fixture DB. No production tokens, real users or sample records are included. P06 is **HTTP failure with persisted mutation**, not a successful response. P09 is **HTTP success with failed sample insertion**. P10 proves resolver behavior, not that every downstream route currently grants the inferred access.

## Downstream dependencies traced, not claimed fully validated

- Reception: project selection, default bundle application, draft recovery/discard, pre-registered IDs and project lab destination.
- Laboratory management: project summaries, owner/service membership, deactivation impact and transfer work.
- Staff: explicit project associations and User.projects; current session checks must remain effective after grants change.
- Dashboards and workbench: projectCode queries, lab/task scope, physically received vs expected, existing work item readiness.
- Reports/SIS: both project relationship and projectCode are consumed; unlinking is therefore an integration risk, even if old exported PDFs are immutable.
- Kobo: scheduler, config selection, sample provenance, retry cursor and project admission state.
- Help, five locales, notifications and deep links: existing framework should be extended, not replaced.

## External guidance used

Authorization must deny by default and be evaluated for each request, including resource scope: [OWASP Authorization Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html). This informs the proposed shared policy and negative tests; it is not a substitute for laboratory-specific rights.

Server-side workflow checks belong at the API boundary: [OWASP REST Security Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/REST_Security_Cheat_Sheet.html). Modal review screens need labelled dialogs, keyboard focus containment and focus restoration: [W3C modal dialog pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/).

Kobo v2 identifies the form asset separately from a submission. The importer must preserve those identifiers and the configured destination rather than guessing a project: [Kobo API introduction](https://support.kobotoolbox.org/api.html), [Kobo v2 migration documentation](https://support.kobotoolbox.org/migrating_api.html). Retry/deduplication rules in this package are a proposed LIMS design, not a claim that Kobo enforces them.
