A new graph run against the cde8 image cannot pass, because the slow work is inside the app. Reading the source at cde8 (this is from the code, not a measurement), `assertOrderRevisionStartupReady(dbPath)` at server/index.js calls `installOrderRevisions({dbPath})` in full. Each startup, that path does the following:
1. It runs `assertLabPolicyStartupReady`, which takes a complete readonly snapshot copy of the DB.
2. It runs `assertControlChartStartupReady(copy)` again on that copy, although index.js finished the same check one line earlier.
3. It runs a full `integrity_check` and a full `foreign_key_check`, plus the schema object checks.
4. It runs the `impact()` scans: ACTIVE revisions/lines, OPEN attempts, open and ACCEPTED WorkItems, and SAND/SILT/CLAY owners with a per-sample lookup.
5. It takes a full SHA-256 of the DB triple through `fileHashes`.

On the production-sized DB at 805 MB, that work is enough to explain why 080000 only finished after its readiness window and 100000 never reached READY.

**Scope of the correction (a codex/* PR, through the normal audit):**
- The order-revision startup check must be read-only and must not copy the DB. It reuses the lab-policy and control-chart readiness results already computed in the same startup, so no snapshot is taken and neither check is repeated.
- Full `integrity_check`, `foreign_key_check` and full-file hashing are removed from the startup path. They stay available in the install/dry-run CLI, which keeps its current behaviour and output.
- The startup check proves only what startup needs: the required schema objects exist and the impact counts are zero. It runs the impact queries in one readonly transaction, with indexed set queries instead of per-sample lookups. Any index it needs comes from a separate additive migration.
- Every READY event (all 26) gains `elapsed_ms` and `rss_bytes`, so the next proof shows where startup time goes.
- Tests:
  - A check that a startup over a non-zero impact still refuses, exactly as before.
  - A regression test that the startup path does not call snapshot, integrity_check or fileHashes.
  - A timing test on a seeded large fixture.
