# Audit evidence and implications

Audit date: 8 September 2026. Source baseline: `e5fa3baea7f0056481a615b0eed4a76572946962` plus Antigravity's in-progress visual modifications. Per-file hashes and dirty files are in source-audit.json; this is a moving checkout, not a clean released snapshot. No application or production data changes were made by this audit.

## Verified findings

| ID | Evidence | Consequence for the redesign |
|---|---|---|
| M01 | `client/index.html` has a viewport and apple-touch-icon, but no manifest link. Public source scan found no manifest/service-worker files; Vite registers only the React plugin. No offline-store/PWA/native-shell dependency in package.json. | Establish install metadata, local boot assets, offline storage and lifecycle deliberately. Absence of a manifest does not mean modern iOS cannot add the website to its home screen; installation alone does not provide offline work. |
| M02 | `App.jsx` uses h-screen, overflow-hidden, a fixed translated sidebar, persisted desktop collapsed state and an internal scroll container. | Separate phone navigation state from desktop collapse preference. Address safe areas, keyboard viewport, focus/inertness, scrolling and route restoration. |
| M03 | Live Chrome viewport 390×844: shared header account button extended from x=362 to x=442; the right side was clipped. Several header controls measured 36px, and dashboard selects had 17px control boxes. | Compact phone header; 44–48px product targets; move appearance/language/profile into a reachable account sheet. These measurements are usability targets, not a full WCAG conformance assessment. |
| M04 | Live workbench at 390px: seven-column queue table measured 578px; Activity Receipts tab extended x=383–465. The viewport screenshot showed lateral navigation and worksheet content off-screen. Audit account SUPER_ADMIN had zero work items. | Phone cards and progressive task detail; preserve a proper tablet/desktop worksheet. Real populated technician batches still need testing. |
| M05 | `WorksheetArea.jsx` has 130px sample, 220px determination and 120px readiness minimums plus selection/details columns, fixed-width search and a docked inspector. | One active sample editor on phones; list/detail or sheet inspector on tablets. Do not shrink the desktop spreadsheet until every column is unreadable. |
| M06 | `WorkbenchShell.jsx` holds edits in React state, waits 800ms, then posts `/api/workbench/batch-save`. On any save error it sets syncStatus='offline'. No durable local outbox is present in that path. Successful queue fetch can set 'saved'. | Persist locally before showing saved; distinguish network failure, unauthorized session, validation/conflict and server acceptance. Page lifecycle cannot be trusted to flush a timer. |
| M07 | `Reception.jsx` uses global `limsi_intake_autosave`, restores only WALK_IN, and saves on a 10-second interval; comment explicitly excludes project mode. Scanner settings also use global localStorage. | Replace with account/lab/device-scoped durable drafts for every intake type. Protect original project sample context. Do not treat this old autosave as an offline implementation. |
| M08 | Live phone reception opening screen gives a prominent Wedge Fast Mode / keyboard suffix / audio strip before the intake choice. | Prioritize Scan, identify and receive; retain external scanner configuration in Scanner settings. Do not remove existing reception modes under this redesign. |
| M09 | AuthContext caches token/user in localStorage, calls `/api/auth/me`, and logs out on 401/403; client fallback role permissions exist. | Dedicated offline enrollment/unlock and server-issued scoped work authorization are required. A cached role object is not an offline access grant, and logout must not silently lose unsynced evidence. |
| M10 | Server has WorkItem.version, WorkItemDraft, command receipts, workflow contract, readiness/validation services, operational confirmation and completion/submission preview/commit routes. | Extend these contracts and services. Do not create a second set of mobile workflow rules or blindly replay raw requests. Existing idempotency is a starting point, not proven coverage of every mutation. |
| M11 | QRScanner uses html5-qrcode with a 250×250 scan area, lifecycle clear calls, and a fixed overlay. Reception has a keyboard-wedge mode. | Retain supported decoders; redesign permissions, rear-camera preference, duplicate debouncing, manual lookup and scanner-wedge focus. Never navigate automatically to arbitrary QR URLs. |
| M12 | Batch/spectral dialogs combine fixed overlays, 92vh heights and nested scroll regions. Notification drawer is translated offscreen; its content and the closed navigation remain in the accessibility snapshot. | Shared responsive overlay contract with explicit closed/inert state, focus restoration, keyboard-safe actions and one content scroll region. AX presence alone does not prove focusability; verify keyboard/screen-reader behavior. |
| M13 | Sample page at phone width places several management actions above the next-action section; five sample tabs sit below a tall identity/action stack. | Compact identity plus current task first, all permitted secondary actions in a labeled menu, visible current section selector. |
| M14 | Live expected sample `400a0c7e-7f48-40ba-9d10-cbbe98fdcce7?tab=request` displayed 0 ordered analyses, 0 verified results and an apparently enabled “Final approve sample” control, while next action was receipt. The action was NOT invoked. | Baseline functional review required: reconcile capability/guard behavior before mobile promotion. This audit does not establish that the backend would approve it. Do not hide or recolor a guard problem and call it solved. |
| M15 | Workflow includes graph/floorplan/detail/export components; reports, spectral charts, maps and master tables have intrinsically two-dimensional content. | Provide touch controls plus an accessible linear equivalent. Preserve scientific axis direction, units, values and full workflow dependencies. |
| M16 | Main header notification accessible name exposed raw plural-message syntax on live phone view. Source workbench files still contain English labels during concurrent appearance work. | Preserve localization adapters; include accessible text and five-locale validation in mobile QA. Do not assume a catalogue completion percentage covers every interface. |

## Scope and limits

The source scan covered 168 JS/JSX/CSS files and 35 route declarations. Its 509 candidates include 37 fixed-width, 61 table/scroll, 76 overlay and 82 storage matches, among others. A match may be intentional and appears in more than one category; it is not a defect count or a percentage of mobile readiness.

Read-only live checks used the existing SUPER_ADMIN session in a dedicated Chrome tab at 390×844. Dashboard, reception, project selector, sample request and workbench opening states were inspected. No sample intake, result, approval, upload, permission or preference was saved. Temporary viewport override was reset and the audit tab closed. Offscreen notification content was not copied into this evidence.

Not verified in this pass: physical iPhone/iPad/Android devices, Safari/WebView behavior, keyboard/OS suspension, camera hardware, native signing, populated technician runs, offline persistence or replay. These are explicit release gates, not implied passes. The current visual branch may alter sizes after these observations.

At package completion the shared checkout had advanced to `16908a4` (spectral runtime/hook fixes), following `b3e3faa` (approved signature visual refresh). The initial source evidence remains pinned to `e5fa3ba` and its captured dirty state. This later Git observation is not verification that the new build is deployed or that the mobile findings have been fixed. Reconcile the final visual baseline before implementation.
