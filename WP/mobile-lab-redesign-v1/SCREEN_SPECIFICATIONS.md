# Complete mobile screen specification

Use these screen contracts with the existing route register; this is not permission to hide features. Each route/tab/dialog requires a phone and tablet disposition and an offline status. Common shell/controls use SoilFER signature and the existing five-locale/theme system. Translate new mobile and sync wording through the shared registry.

## Role opening and navigation

| Role/capability | First useful view | Frequent phone destinations |
|---|---|---|
| Technician | Continue current method run; returned work; today's downloaded pack and blockers. | Home, Work, Scan, Samples, More. Work routes to the canonical workbench; My Work is assignment context, not another result editor. |
| Reception | Resume incomplete intake, scan next specimen, active consignment and expected arrivals. | Home, Receive, Scan, Samples, More. |
| Lab manager | Submitted work needing review, exceptions, assignments and device-sync conflicts. | Home, Review, Scan where allowed, Samples, More. |
| QA/auditor | QC/equipment exceptions and permitted evidence/audit views. | Home, Quality, Reports, More; sample/scan access only if actually granted. |
| Project manager/master user | Scoped project arrivals/progress, exceptions and reports. | Home, Projects, Samples or Reports according to capability, More. |
| Super administrator | Global configuration issues and scope selector, with lab-specific drilldown. | Home, Labs, Users, More; all permitted destinations remain reachable. |
| Surveyor/viewer/other supported roles | Current authorized project/sample/read-only view. | Derive from actual capabilities; do not hardcode broader access from this table. |

Maximum five bottom items, each with icon and visible translated label. Do not reorder them because counts changed. Account/lab context and Sync Centre remain reachable. Profile and global language/theme preferences do not share storage with another user. Tablets use an adaptive rail and pane arrangement; desktop keeps the established navigation.

## Action design and safety

Primary action is computed from current authoritative capability plus local pending context, not from a mobile-only status mapper. A phone must not promote “Final approve” on an expected sample. Server checks remain decisive even if an action is hidden/disabled. Distinguish permission denial, prerequisite blockage, outdated pack and a missing connection with specific reasons.

Avoid overusing bottom sheets: use a short sheet for filters/choices, a full-screen route/dialog for long forms and evidence review. Give every sheet/dialog an accessible title, explicit close, focus restoration and dirty-state protection. Back/gesture handling cannot silently abandon an unsaved result. Keep final actions above keyboard/safe area without obscuring content.

Scan feedback shows the full specimen ID and target method/run before entry. Repeated scans of the same code do not duplicate an intake or advance silently; different scan during dirty entry offers save-and-open or stay. QR strings are parsed against approved LIMS identifiers/hosts with local matching; reject arbitrary actions/URLs and show ambiguous matches.

## Example shift

The technician downloads a 40-sample pH run with instrument and QC context. During Wi-Fi loss, they scan a specimen, confirm its identity, enter a qualified value, and move to the next sample only after a local save. A compact run index shows 27 captured, 2 needing attention and 11 untouched. They review and seal the ready records, then reconnect. The server accepts unaffected samples and returns one assignment conflict. The conflicting local value is retained for review; no duplicate measurements or silent overwrite occur.

A reception officer downloads a project consignment, receives five identified specimens and captures arrival photos offline. A technician may continue under the same authorized device/pack only where the workflow policy and actor grant permit it. Separate disconnected devices cannot see new receipts until synchronization or an explicitly designed secure handover; the UI must never pretend they share instantaneous state.

## Prototype boundary

The interactive study demonstrates task layout, switching among a few sample records, grouped entry, offline/sync labels and conflict review. It does not activate a real camera, persist lab data, authenticate, run scientific classification, upload files or synchronize. It is not a template to replace actual controllers/components. Tablet design controls illustrate composition; real iPad split-screen and soft keyboards are release tests.
