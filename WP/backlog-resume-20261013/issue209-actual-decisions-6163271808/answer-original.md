## 1. Existing multiple ACTIVE revisions: your proposal is accepted, with conditions

Do not require a separate repair. A repair would be the same operation, a deliberate reasoned revision, so `ORDER_REVISION_REPAIR_REQUIRED` would only add friction.

- **No installer cleanup.** The installer touches no revision row. Its dry run reports the number of samples with more than one ACTIVE revision, with their ids. That count goes into the deploy kit.
- **The command states the full target set.** When the sample has more than one ACTIVE revision, the command must state the complete set of analyses. It must not be a delta against one guessed revision. Reconciliation compares that set with the actual WorkItems, never with a chosen "latest" revision.
- **One transaction.** Every prior ACTIVE revision becomes SUPERSEDED, keeping its lines and values, and one new ACTIVE revision is created. The audit row lists every superseded id and `priorActiveCount`.

  - A sample with three historical ACTIVE revisions ends with one ACTIVE and three SUPERSEDED, with every line unchanged.

- **New links.** `OrderLine.workItemId` is nullable. It is written only on new lines and is fixed after insert. Retained attempts keep their `orderLineId`. An already-reserved historical OPEN attempt completes its first fill with its original null identity and is not relinked. That is correct under the #190/#191 identity guards, and it is forward-only.
- **Refinement: legacy resolution before refusal.** Most existing work items will have no `workItemId` link after the migration. A blanket `ORDER_LINE_REQUIRED` would stop routine work on every in-flight sample after deploy. So a new attempt resolves its line in this order:
  1. the line whose `workItemId` equals the item;
  2. otherwise, for a legacy line with a null `workItemId`, exactly one line matching (sampleId, normalised analysisCode) within exactly one ACTIVE revision.

- **When to refuse.** Refuse `409 ORDER_LINE_REQUIRED` only when there are zero matches, more than one match, or more than one ACTIVE revision. The message should tell the user that a reasoned order revision fixes it.
