**Binding before start.** For a run newly started for an analyte evaluated in CONTROL_CHART mode, every LRM position it serves must have its `ReferenceMaterial` lot bound **before start**. Otherwise start is refused with a stable 4xx code, e.g. `QC_CHART_LOT_REQUIRED`. The message should name the unbound QC position. Late binding is not retained in chart mode, because the series key, the limit basis and the frozen history all depend on the lot.

There are three refinements:

1. **What counts as chart mode.** It is decided by the frozen QC rule or policy for that analyte and method at start, not by whether an approved `ControlLimitSet` happens to exist. A chart-mode series that is still **Provisional** (fewer than the minimum points) also requires binding before start, because the provisional point count and the eventual baseline are per lot.
2. **The lot is fixed after start.** For chart-mode positions, the lot bound at start is frozen with the start criteria. A later attempt to re-bind or change it is refused with a stable 4xx code. Using a different lot means using a different QC position or a new run.
3. **Existing behaviour is unchanged.** FIXED_WINDOW analytes keep late binding at first measurement. Runs already started before this release keep their original behaviour and frozen criteria. No past criteria, evaluations or bindings are rewritten, and the change in `audit_2_3_native_runs.test.js` is limited to adding the new chart-mode case. The existing late-binding case for fixed-window still passes unchanged.

Tests should include:
- chart-mode start refused when a lot is unbound;
- the provisional chart-mode case refused in the same way;
- fixed-window late binding still accepted;
- a run started before the release still accepted on its old path;
- re-binding after start refused.
