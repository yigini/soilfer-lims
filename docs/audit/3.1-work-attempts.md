# Audit 3.1: WorkAttempt evidence

Issue #190 and its scope-update comments define this release. This checkpoint
is not ready for audit or deployment; full-suite verification and the final
owned-copy rehearsal remain pending.

The additive migration retains every original attempt field and existing
Result link. It adds nullable attempt metadata, a Batch foreign key and
ReviewDecision.reasonCode. Historical duplicate attempt numbers are reported
and every member of each group is flagged before the partial uniqueness index
is installed. No attempt is renumbered. New executions allocate max+1 across
all attempts, including flagged historical rows, inside their transaction.

New executions insert their complete, immutable evidence before any Result.
Replicates and texture fractions/class from one execution share one attempt.
Attempt and Result equipment evidence use the same frozen readiness snapshot.
Historical equipment evidence comes only from identical stored Result
snapshots; missing or conflicting snapshots remain NULL and are reported.
Historical batch evidence is copied only from an existing referenced Batch.

The sole NULL-attempt exemption is an IMPORTED Result with no canonical
WorkItem for its sample and parameter. Every other new Result requires an
attempt. Ordered parameters without canonical work are refused rather than
creating work in a result writer. Missing ordered work is counted by lab and
parameter in the dry-run and receipt. Automatic texture derivation keeps
recorded fractions and reports a skip when no TEXTURE WorkItem exists.

Analytical review derives a link only when one attempt has current Results.
Several candidates require an explicit valid selection. An unexecuted OMIT
decision may remain unlinked; non-measurement review keeps its existing
workflow. Bulk review preflights all links and commits atomically.

Run both commands against a fresh owned copy before any approved release:

```sh
node server/scripts/install_work_attempt_contract.js --db /absolute/owned/copy.db --dry-run
node server/scripts/install_work_attempt_contract.js --db /absolute/owned/copy.db --apply
```

The installer refuses partial, altered or unmarked guard/receipt states and
unresolved historical matches. Schema, backfill, guards and the integrity-bound
receipt commit in one immediate transaction. Repeating a complete installation
is a zero-write NO_OP. Startup verifies the completed installation read-only
before loading application writers. Docker retains the exact migration source
outside Prisma's migration directory.
