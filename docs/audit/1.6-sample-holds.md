## Runtime behavior

- Undo/reject cancels eligible WorkItems with INTAKE_UNDONE/INTAKE_REJECTED provenance, retaining every row. Results, scans, evidence, attempts, drafts, equipment/inventory use, batch membership and sealed work refuse the entire operation. Already cancelled rows are skipped with their original attribution intact. Cancellation/reactivation requires the private intake action; clients cannot write cancelled items or supply cancellation fields. Legal reacceptance normalizes expanding/alias analysis codes, reuses requested intake-cancelled work, retains cancellation history, clears assignment timestamps, keeps dropped analyses cancelled and refuses legacy cancellation conflicts.
- Acceptance and central assignment use the canonical hold service. Assignment events (NOT_ASSIGNED to ASSIGNED or a change of assignedTo) admit only ACCEPTED/PROCESSING samples and refuse holds. Reassignment uses that same transaction and roles configuration; sealed/cancelled items refuse. Plain edits and draft reverts are exempt from the assignment gate. Operational gate recovery restores the sample before restoring its assignment in the same transaction.
- Open SampleHold rows or active/invalid legacy metadata/mirror markers block the sample. Intake, assignment, workspace/list/lookup and exchange readers share JS/SQL helpers, including pre-#183 database readers. New Kobo holds write the row and compatibility marker atomically and retain earlier resolution history.
- Scoped hold APIs enforce VIEW_SAMPLES and manager APPROVE_RESULTS through roles configuration. Resolution requires a reason and commits attribution, compatibility updates and audit together. Only the last open bound Kobo hold clears its marker/mirror. List/reception/workspace badges and resolution UI use all five locales; legacy updatedAt attribution is explicitly an upper bound.
- Wrapper-only resolution adds a metadata marker only after the last bound hold closes, preserving all unrelated metadata bytes and all wrapper fields. Its audit records before/after metadata hashes. Malformed roots/markers refuse with HOLD_MARKER_INVALID and retain raw text. Repair is deferred to [#247](https://github.com/yigini/soilfer-lims/issues/247).
- Metadata edits cannot forge provenanceHold. Malformed Kobo submissions are skipped with HOLD_MARKER_INVALID while later healthy submissions commit; the cursor stays before the gap so repaired submissions can be retried. Re-raised holds retain historical resolutions and remove stale resolution-association flags. Exchange trigger version 12 reinstalls canonical/wrapper hold checks on existing databases.

## Additive installation

`20261006000100_sample_holds_cancellation/migration.sql` adds four nullable WorkItem history columns and a new SampleHold table. It adds an open-hold index, one-backfilled-hold-per-sample partial unique index and seven integrity triggers. Raise fields are immutable, resolution is final and deletes are refused. No old data, guards, tables, indices or audit rows are removed or rewritten. Attribution sources and compatibility bindings are checked in SQL. The unreleased #183 SQL and its digest were updated under [Claude's failed audit](https://github.com/yigini/soilfer-lims/pull/248#issuecomment-6010057190); frozen #179/#182 sources and the Docker boundary probe remain unchanged.

The digest-bound loader supports source and immutable Docker migration paths. The installer classifies exact PRE_183, FRESH_PRISMA or COMPLETE shapes, validates populated data, refuses partial/forged schemas, applies in one transaction and records `183_sample_holds_cancellation`. Repeat apply and direct startup are read-only/no-op. Docker entrypoint installs before server startup; direct startup requires a complete installation. Installation does not backfill or reject malformed legacy metadata.

```sh
node server/scripts/install_sample_holds.js --db /owned/copy.db --dry-run
node server/scripts/install_sample_holds.js --db /owned/copy.db --apply
```

Production installation requires the existing reviewed release procedure: stopped writers, database/assets backup, owned-copy installation and candidate/rollback startup rehearsal, preservation checks, then live apply and authenticated postflight. Report installation, backfill and malformed-row counts. This branch has no production changes.

## Reviewed legacy backfill

```sh
node server/scripts/backfill_sample_holds.js --db /owned/copy.db --dry-run
```

Dry run inventories every marker and reports proposed mappings, refusals, inconsistency diagnostics, upper bounds, metadataRepairNeededCount and alreadyBackfilledInconsistentCount with zero writes. An unreadable fieldMetadata root without a readable marker is a repair-only diagnostic; no Kobo hold is invented. Already backfilled inconsistent markers remain held and are diagnostic only. Neither diagnostic refuses valid mapped rows. Automatic mapping is limited to the three known Kobo reason prefixes and ACTIVE metadata markers. Use the earliest matching conflict audit timestamp, otherwise valid marker updatedAt. The hold raiser is always system:kobo-sync; preserve the matched legacy actor verbatim as triggeringUser in audit details. Other invalid/missing/future/pre-sample timestamps, unknown producers/statuses/mirrors, wrapper-only markers and malformed roots/markers require reviewed mapping. Clock skew tolerance is bounded at the scope pin's maximum 24 hours.

For each refused row, a reviewed JSON document has only `rows`; each row has `sampleId`, the dry-run row's `fingerprint`, ISO `raisedAt`, allowed existing `raisedBy`, `holdReason`, `reviewer` and `reviewReason`. Its exact file SHA is required. No mapping may invent a human raiser. Review all refused rows before apply; the entire operation refuses with zero writes if any remain.

```sh
node server/scripts/backfill_sample_holds.js --db /owned/copy.db --dry-run \
  --mapping /review/holds.json --reviewed-mapping-sha256 <exact-file-sha>
node server/scripts/backfill_sample_holds.js --db /owned/copy.db --apply \
  --mapping /review/holds.json --reviewed-mapping-sha256 <exact-file-sha> \
  --plan-sha256 <fingerprint-from-reviewed-dry-run> --operator <active-manager-username>
```

When no reviewed rows are needed, omit both mapping flags. Apply still requires the exact dry-run plan fingerprint and checks it again under the write transaction. Under [operator pin 6010138199](https://github.com/yigini/soilfer-lims/issues/183#issuecomment-6010138199), an explicit active human User with APPROVE_RESULTS and scope over every proposed sample is validated in that same transaction. Invalid/forbidden/out-of-scope operators refuse with stable BACKFILL_OPERATOR codes and zero writes. System/service actors cannot run apply; dry run needs no operator. Each mapped sample adds one bound SampleHold and one HOLD_BACKFILLED audit row attributed to the operator; an additive migration receipt records counts, review digests and operator. Original metadata/fieldMetadata, science/QC and every old audit row are unchanged. Repeat apply is a zero-write no-op. Reviewed malformed markers remain held and visible, and cannot be resolved until #247 supplies an explicitly reviewed repair.
