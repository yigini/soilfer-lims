# Reference materials — audit 2.1 (#184)

WIP on merged #182/main. The absence of catalogue models and the unlinked control write path were confirmed before implementation. Scope pins [6009757542](https://github.com/yigini/soilfer-lims/issues/184#issuecomment-6009757542) and [6009891898](https://github.com/yigini/soilfer-lims/issues/184#issuecomment-6009891898) govern the work.

The foundation adds a per-lab material/certificate/lot catalogue and immutable assigned values, with nullable certificate coverage factor. Correction creates a replacement and supersedes the old value atomically; it never changes the recorded value fields. Linked QC controls retain their value and placement snapshot. Current generic and method-specific values use separate partial unique indexes.

Eligibility uses stored expiry instants and linked inventory eligibility. The effective expiry is the earlier material/lot instant. Reading expiry never writes a status. Only the expiry warning uses a per-lab policy value (`referenceMaterials.expiryWarningDays`, shipped default 30). Calendar cutoffs are deferred pending a timezone policy. Control charts and real run-member positions remain outside #184.

The generated Prisma client validates the schema. The initial eligibility/conversion contracts pass 14 tests on a new owned database created from actual Prisma-generated DDL; its operational tables start empty. Managed-worktree Windows path matching prevented Jest discovery there, so validation runs in an owned clone outside that path. No repository test configuration was changed. The captured fresh-Prisma table definitions contain schema only.

The additive installer and read-only startup gate validate the exact release objects, nullable typed-QC links and supersession targets. Both legacy populated and fresh-Prisma fixtures preserve every historical QC/result field and old schema object. Installation backfill count is zero; dry run, refused plans and repeat/startup checks write nothing. An installer receipt fault rolls back the entire installation.

The Admin → Quality catalogue lists lots, status, effective days to expiry and policy warnings, with per-analyte current and superseded values. Certificate facts cannot be edited in place. A correction requires a reason and creates a new revision. Manual status changes require an audited reason. The existing QC form offers eligible reference lots and explicit CRM/LRM use; expected values and method anchors are resolved on the server. An unchanged saved link retains the original value and placement snapshot even after expiry or a certificate correction. Unlinked legacy controls remain usable.
