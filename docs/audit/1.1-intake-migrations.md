# Intake integrity migrations

Run `node server/scripts/workitem_duplicates.js --database <existing SQLite file>` before release. The default is read-only and works before the new column exists. Record the group count in the release receipt. Stop the release if any group exists; never choose a canonical item automatically.

For an installation with duplicates, back up the database and stop all writers. Apply only `20261004190000_add_workitem_duplicate_marker` first. A manager must review each group, including `HAS_RESULTS` warnings, and explicitly resolve it:

```text
node server/scripts/workitem_duplicates.js --database <existing file> --resolve --sample <sample ID> --analysis <analysis code> --keep <WorkItem ID> --reason "Manager's reason" --actor <manager username>
```

The command marks the other active items with `duplicateOf`, records one audit row for each changed item, and preserves all results, submissions, batches and history. It refuses stale groups and invalid kept IDs. Re-run the read-only listing; continue only at zero groups. The next migration installs the partial unique index. Duplicate groups cause index creation to fail, leaving the index migration unapplied. The marker migration is independently additive so managers can resolve existing duplicates before the constraint is installed.

Undeclared consignment counts become nullable without changing any existing count or code. Release verification must record the consignment count and a SHA-256 fingerprint of `(id, code, expectedCount)` before and after migration, and verify that all foreign keys and indexes remain intact. No historical counts or consignment codes are back-filled.

Run `node server/scripts/consignment_schema.js --database <existing file>` before and after the nullable-count migration to obtain those receipts. This reader streams consignment tuples and opens the database read-only. The SQLite rebuild disables FK enforcement **before** starting its transaction, preserving child `Sample.consignmentId` links rather than triggering `ON DELETE SET NULL`. It copies all 29 columns and recreates the three existing indexes, then checks foreign keys before commit and restores enforcement.

The migration refuses extra consignment columns, custom indexes, triggers or foreign keys, rather than discarding unrecognized schema. Such an installation needs a separately reviewed migration that explicitly preserves its custom definitions. On any migration failure, the release runner must roll back the connection and restore FK enforcement; do not continue a failed release.

Marked duplicates are excluded only from canonical per-analysis lookup and work/gate generation. Publication completeness, review atomicity, result invalidation, QC disposition, retention and other safety checks continue to inspect every row. Managers must waive unworked duplicates through the existing reasoned, audited path; marking a duplicate never makes unfinished work publishable. The test database installs the actual partial index even when its schema was initialized with Prisma db push.

Scope decisions on #178 preserve the two-step arrival boundary: no lab sample code, WorkItem or order at physical arrival; final acceptance rechecks current facts. Zero grams is a valid observation and stays zero. Mass uses implicit grams (or explicit `g`); other units are refused without conversion. Configurable required custody fields are deferred to chain-of-custody policy work. Checklist configuration, the general sample state machine and repeat WorkAttempts remain outside this issue. No existing sample/code/count receives a back-fill in this release; duplicate resolution occurs only for explicitly reviewed groups.
