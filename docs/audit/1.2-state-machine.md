The original findings remain. Import creates APPROVED directly; preparation and
workbench paths write status directly; adding analyses can reopen final samples;
undo-approval reverts accepted work and deletes post-analytical items. Intake paths
were centralized in 1.1, but still need the common state services for every write.

Implementation in progress; this branch is not ready for audit or deployment.

The contract foundation adds the approved states and read aliases, removes the
APPROVED-to-PROCESSING edge, and generates the client contract from the exact server
bytes before builds. Unknown legacy values remain unknown. ON_HOLD graph edges
are additionally restricted to the recorded prior status by the state services;
verification edges are restricted to configured operational confirmation and
manager verification. WorkItem CANCELLED remains a legacy terminal value.

No production state migration has been run for this issue.

The current foundation includes central creation/transition services, hold recovery,
conditional status/version updates, immutable reviewed migration plans, additive
SQL guards, and preparation evidence helpers. Caller integration is incomplete;
the presence of these helpers alone does not satisfy acceptance criteria.

Operational confirmation and verification now resolve the author-pinned
`gate.verificationRequired` policy in the write transaction. All presets default
to false; DRYING/PREPARATION may override it at analysis level. Request true can
strengthen the policy, and false cannot bypass it. Both paths advance ACCEPTED
to PROCESSING when the last gate completes. Phase changes and preparation
reverts use the services and append result evidence atomically. Undo approval
always refuses with AMENDMENT_WORKFLOW_REQUIRED. Publication checks preparation
evidence before any report writes. Manager clearance has a scoped API endpoint.

Intermediate validation on the isolated copy: nine focused suites / 167 tests
passed (6.503 s); the earlier client build passed (17.28 s), lint passed with 0 errors and the 14
existing warnings. Prisma schema validation/generation passed. The full server
suite remains required after all caller integration and the migration CLI.

Historical epoch timestamps are read without rewriting their storage format.
State CAS uses the original raw status (and work-item version / migration marker)
inside the SQLite transaction; reviewed migration plans also verify the read
timestamp before writing. This avoids invalid equality predicates that bind a
historical integer timestamp as ISO text.

Deferred by the author: historical import still uses a laboratory ID in Sample.labId,
which audit 1.3 designated as the legacy sample-code alias. This issue preserves
that existing import behavior and does not invent an approval identity.

Both analysis-edit routes now commit reconciliation, the order snapshot, Sample
state, command receipt and audits in one transaction. Final Sample states refuse
even no-op edits with AMENDMENT_WORKFLOW_REQUIRED; adding new work to
SUBMITTED_FULL resumes PROCESSING centrally. Reconciliation re-reads the Sample
in that transaction. Per the author's additional scope update
[5985600614](https://github.com/yigini/soilfer-lims/issues/179#issuecomment-5985600614),
removing COMPLETED, ON_HOLD or AWAITING_VERIFICATION work returns
WORKITEM_REMOVAL_STATE_CONFLICT with each blocked item and its resolution path,
before writes. Existing recorded-result and duplicate-reference refusal remains.

QC dispositions use the central WorkItem service and preserve final work/sample
histories. Both repeat decisions write REPEAT_REQUIRED; existing repeat aliases
retain their state and review provenance while appending history. A held or
unverified member refuses the whole decision. All three manager review routes
retain their status/version/submission compare-and-set, one WorkItem review audit,
and transaction rollback. New ReviewDecision omission rows use OMIT. Gate RETURN
records preparation-reversion evidence in that same review transaction.

Legacy closure endpoint regressions execute against isolated, schema-only test
databases populated before the exact additive release SQL. No template data is
copied and no constraint is dropped or disabled. This preserves real PENDING
compatibility coverage while ordinary fixture creation uses allowed states.

The 167 passing checks cover these new behaviors and existing review concurrency,
legacy review, QC flagging, duplicate reconciliation, removal and permission gates.
No full-suite result or audit readiness is claimed at this checkpoint.
