Base: `66e119ab212d226fb7d6030435c4f6bf9c9e7ae7` (audit 1.1 merged).

and [reviewed legacy upgrade](https://github.com/yigini/soilfer-lims/issues/179#issuecomment-5992624804).

## Runtime behavior

All initial Sample and WorkItem states and subsequent writes use
`sampleStateService` or `workItemStateService`. They validate actor, lab scope,
legal edges, hold recovery and conditional status/version updates in the caller's
transaction. The state write and its audit either commit together or roll back.
System import/sync jobs have named actors. The obsolete synchronous status
writers in `db.js` have been removed.

The shared contract adds DRAFT, ON_HOLD, AWAITING_VERIFICATION, REPEAT_REQUIRED
and CANCELLED. A hold records its prior state; resuming requires the recorded
edge and reason. REANALYSIS_REQUIRED remains a read alias. Unknown historical
values keep loading and are reported without guessed mappings. The client build
generates its contract from the exact server bytes.

Intake, manifests, Kobo, offline receipts, drafts, analytical work, preparation,
submissions, reviews, QC decisions, closure tasks and spectral evidence changes
use these authorities in their existing transaction. Final-parent reopening,
analysis reconciliation, result editing and RETURN actions refuse with
`AMENDMENT_WORKFLOW_REQUIRED`. The amendment workflow belongs to Phase 6.

Operational confirmation resolves `gate.verificationRequired` through
`policyService` in the transaction. All presets default to false;
DRYING/PREPARATION can have an analysis override. A request may strengthen that
policy but cannot bypass a required verification. The final completed gate
advances ACCEPTED to PROCESSING through the central service.

Authoritative gate WorkItems must agree with stored DONE flags. Disagreement
returns `GATE_STATE_MISMATCH`. Where an old lab has no gate WorkItem, the stored
DONE flag is allowed as the pinned legacy evidence and recorded in the authorized
audit. A read-only inventory reports that reliance by lab; it creates no work.

Preparation reversion requires a reason and appends immutable
`ResultEvidenceEvent` records. It preserves Result values. Uncleared
PREP_REVERTED evidence blocks submission, review and publication. A scoped
manager action clears the flag with a reason and another evidence/audit row.

Submission lifecycle is derived by one shared pure calculation; persistence
occurs through the state authority in the submission transaction. Lazy catalogue
prerequisites resolve from a fresh transaction snapshot, and missing required
work blocks execution. Map/readiness displays do not save derived state.
Returned analytical work uses REPEAT_REQUIRED and retains the old read spelling.

Spectral upload, link, commit, trash and review protect both the current and prior
evidence owner. Changing evidence on completed work requires a supplied reason
and a central reopen/recompute path. Prior completion identity is retained in
history/audit. Unchanged scan contribution leaves the WorkItem unchanged.
Scientific values, scan provenance and previous submissions are preserved.

Review routes retain scope, conditional state/version checks and atomic
ReviewDecision/WorkItem/Sample/audit commits. The manager dashboard counts current
APPROVED events by `approvedAt` in the laboratory's day, rather than historical
COMPLETED rows or unrelated `updatedAt` edits.

## Additive schema and source enforcement

The two Prisma migrations add only:

- Nullable `holdPriorStatus` and `legacyStatus` to Sample and WorkItem.
- The append-only ResultEvidenceEvent table and its indexes.
- Eleven INSERT/UPDATE guards for Sample, WorkItem, Batch and ReviewDecision.

There is no table rebuild, DROP, analytical/QC/audit deletion, constraint
disabling, or automatic status back-fill. Existing rows remain readable.

`server/services/workflowMigrationSources.js` is the one closed source loader.
It reads the exact committed LF bytes, validates both SHA-256 digests, and has
no environment-based source override. Container sources are copied by Docker to
`/app/server/.migrations-backup/179/<directory>/migration.sql`, outside the
persistent database volume. Local CLI use reads `server/prisma/migrations`.

| Source | SHA-256 |
| --- | --- |
| 20261005000000_workflow_state_evidence | ae3accea0c276aab9ea3ed443b44d89ac05e52ef38a39345aa33e8744f019552 |
| 20261005000100_workflow_state_guards | 84921ef45fa8609621b38908de5261d716820f2135f2dde1b9a20fafa6fc81ed |

The AST source guard scans handwritten server runtime, scripts, seeds, tests,
Python and SQL. It resolves only the fixed loader/module digest, its two exact
SQL members, and its pure CREATE-only evidence slice. Unknown SQL, mutable
aliases, other imports/members, tampered bytes, DML or guard disabling remain
findings. There is no installer writer exemption.

Embedded literal programs passed to Node/child-process execution, generated
JavaScript files, Function or vm are inspected for Sample/WorkItem DML. One
declared inventory deferral reports the unchanged #146 minimal synthetic Docker
fault adapter at `server/scripts/rehearsal_docker_boundary.cjs`, SHA-256
`c215311a252b83fb95dcf410d4e9c9bc79c24864ca782123d19631472b226f32`.
Any byte change restores failing embedded-write findings. This is a reported
deferral, not a third helper exception. The four-row, dirty-writer and rollback
tests stay intact; [#245](https://github.com/yigini/soilfer-lims/issues/245) tracks
modernization outside the 55 audit items, per
[5993219622](https://github.com/yigini/soilfer-lims/issues/179#issuecomment-5993219622).

Exactly two pinned test helper exceptions remain: the named `beforeGuards`
export and `rejectedGuardWrite`. Both require a resolved test-owned path,
`NODE_ENV=test` and literal `system:fixture`. Callers receive no exception.
Historical fixtures seed declarative rows into an exclusively created schema
before installing the exact guards. Immutable pre-migration snapshots are
read-only and checked by SHA; they are never used for apply. Pinned historical
schema variants retain their real migration order/equivalence assertions.

The actual-installer fixture option invokes the public child CLI and verifies
all original rows, columns, FKs, indexes and DDL after the allowed additions.
The reviewed option consumes a real immutable-snapshot dry-run record; it never
generates an approval fingerprint. The timestamp-race option changes exactly
one declared candidate's updatedAt, proves a second real dry-run fingerprint
differs, and requires a zero-write stale-plan refusal. These closed options are
pinned in [5992194809](https://github.com/yigini/soilfer-lims/issues/179#issuecomment-5992194809)
and [5992733495](https://github.com/yigini/soilfer-lims/issues/179#issuecomment-5992733495).
No unguarded writable handle returns.

## Installer and ordinary startup

`install_workflow_state_guards.js` defaults to a read-only dry run. It reports
classification, candidate/unmapped/blocked counts and planned statements.
It checks table_xinfo, FK/index definitions, every guard's SQL and the marker.

| Classification | Apply behavior |
| --- | --- |
| PRE_179: none of the additions, evidence table or guards | Execute both exact migrations and insert the marker in one BEGIN IMMEDIATE transaction. |
| FRESH_PRISMA: compatible additions/evidence/indexes, no guards | Execute the exact guards and insert the marker in one transaction. |
| COMPLETE: exact additions, guards and valid marker | Read-only inventory/postflight, zero-write no-op when no status plan is pending. |
| Partial, mismatched or complete-unmarked | Refuse before writes with WORKFLOW_GUARDS_SCHEMA_MISMATCH and the differences. |

The marker is `179_workflow_state_guards` in the existing
`_schema_migrations(id TEXT PRIMARY KEY NOT NULL, appliedAt DATETIME NOT NULL
DEFAULT CURRENT_TIMESTAMP, details TEXT)`. The table is created only if absent.
Details are exactly JSON containing `evidenceSha256` then `guardsSha256`;
existing marker rows remain unchanged. Complete-unmarked schemas are not adopted.

Docker's entrypoint runs the installer with `--apply` after the four existing
migration commands and immediately before serving. A nonzero installer exit
stops startup. The entrypoint supplies no reviewed fingerprint or bypass flag.

After dotenv and before importing app.js, schedulers or listen, index.js runs
the same installer's classification and inventory read-only. It passes only a
COMPLETE schema with exact marker hashes and zero candidate/unmapped/blocked
rows. This gate has no environment, flag or NODE_ENV bypass, including dev.
Docker performs this read-only check after its installer. The success event
reports totalChanges 0 before the app's writable adapter is loaded. See the
[direct-startup pin](https://github.com/yigini/soilfer-lims/issues/179#issuecomment-5992946755).

## Upgrading a lab with legacy statuses

Keep writers stopped throughout steps 1–4. Run the one-off commands in the new
release image with the same database mount and explicit path; bypass the
ordinary entrypoint only to execute the reviewed migration commands. These
examples run from the server directory. Substitute the actual mounted database
path and a separately stored reviewed plan file.

1. Take the usual stopped-writer database and asset backup, retain the rollback
   image and run the normal release disk-reserve checks. Keep the lab from
   serving. Rehearse on a fresh owned backup copy first.
2. Run the status CLI read-only, store its output outside the database, and have
   a human review the complete plan and record fingerprint F:

   ```sh
   node scripts/migrate_legacy_statuses.js --db /path/to/dev.db --dry-run > /path/to/reviewed-status-plan.json
   ```

   Candidate counts may be positive only for the approved mappings. Unmapped or
   blocked counts must be zero; otherwise resolve the evidence/model question
   with the auditor. Never guess a mapping or rewrite provenance.
3. Install the schema with that reviewed fingerprint as a one-off:

   ```sh
   node scripts/install_workflow_state_guards.js --db /path/to/dev.db --apply --reviewed-status-sha256 F
   ```

   The installer reclassifies and recomputes the complete plan under BEGIN
   IMMEDIATE. It checks the review binding and installs only schema, guards and
   marker. It performs no status writes.
4. Execute the unchanged reviewed status apply:

   ```sh
   node scripts/migrate_legacy_statuses.js --db /path/to/dev.db --apply --plan /path/to/reviewed-status-plan.json --reviewed-sha256 F
   ```

   All mapped status changes, exact-original legacyStatus markers and one audit
   per changed row commit through the central services in one transaction.
   Report changedRows/auditsAdded and retain the reviewed report.
5. Start normally. The installer classifies COMPLETE, checks no candidate,
   unmapped or blocked rows remain, and makes zero writes. Record health checks
   and the production receipt.

A separately reviewed revert dry run uses `--revert`; its apply requires its
own complete plan/fingerprint and consumes the original legacyStatus markers.
It preserves scientific values and earlier audit rows. A reverted legacy plan
blocks ordinary startup until the reviewed upgrade is completed again.

## Local and non-Docker startup

Point DATABASE_PATH at the existing lab database, using the same absolute path
for the explicit installer/status commands. A fresh Prisma db push creates the
columns and evidence table but does not install these SQL triggers or marker.
With writers stopped and a reviewed backup, run the installer explicitly before
`npm start`, `npm run dev` or `node index.js`. If legacy candidates exist, use
the five-step reviewed procedure above. The app process performs no schema
writes; it refuses until the installation and status plan are complete.
A missing database returns DATABASE_NOT_FOUND and is never implicitly created.

| Refusal | Operator action |
| --- | --- |
| DATABASE_NOT_FOUND | Set DATABASE_PATH to the existing intended lab file and follow the reviewed setup procedure. |
| WORKFLOW_GUARDS_NOT_INSTALLED | Stop writers and run the explicit installer, using the reviewed legacy procedure if candidates exist. |
| WORKFLOW_GUARDS_ARGUMENT_INVALID | Correct the command; the reviewed flag requires --apply and an exact 64-hex value. |
| WORKFLOW_GUARDS_SOURCE_MISMATCH | Restore the exact reviewed release image/source bytes; do not use volume SQL as a substitute. |
| WORKFLOW_GUARDS_SCHEMA_MISMATCH | Keep the lab stopped and investigate the reported schema/marker differences with the auditor. |
| WORKFLOW_STATUS_PLAN_REQUIRED | Obtain a complete read-only dry run and human review; resolve all unmapped/blocked rows before the one-off install. |
| WORKFLOW_STATUS_PLAN_STALE / STATUS_MIGRATION_PLAN_STALE | The file changed after review. Take a fresh dry run and review; do not reuse F. |
| WORKFLOW_STATUS_PLAN_PENDING | Installation finished but mapping did not, or unresolved status evidence remains. Keep the lab stopped and finish the reviewed status procedure. |
| WORKFLOW_GUARDS_INTEGRITY_REFUSED | Investigate integrity/FK evidence while stopped; the installation transaction rolls back. |
