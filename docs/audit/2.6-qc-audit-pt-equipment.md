## PT schema and legacy evidence checkpoint

Seven nullable PT evidence fields ship in additive SQL with two PENDING/null
NCR guard triggers. The digest-bound installer handles an older table or fresh
Prisma columns, refuses partial/tampered installation, and records a receipt in
the same immediate transaction. It never rebuilds ProficiencyRound or changes
an existing score/outcome. Disposable test global setup installs the PT guards;
Docker and direct startup wiring remain pending.

The separate backfill defaults to dry-run. It lists sigma flags and catalogue
code mismatches, marks only valid-sigma stored UNSATISFACTORY rounds PENDING,
and never reclassifies or normalizes old codes. Applying changes requires the
reviewed dry-run fingerprint and a named active global administrator. Each
changed round gets a before/after audit; an audit failure rolls back all changes.
The receipt includes ids/counts and identical before/after score/outcome hashes.
Explicit historical sigma 1.0 remains valid. Repeating an apply is zero-write.

Before a later audited release, with writers stopped and an owned-copy rehearsal
passed, use the exact release's scripts and retain both JSON receipts:

```sh
node server/scripts/install_proficiency_evidence.js --db /absolute/owned/copy.db --dry-run
node server/scripts/install_proficiency_evidence.js --db /absolute/owned/copy.db --apply
node server/scripts/backfill_proficiency_evidence.js --db /absolute/owned/copy.db --dry-run
node server/scripts/backfill_proficiency_evidence.js --db /absolute/owned/copy.db --apply --plan-sha256 REVIEWED_SHA --by ADMIN_USERNAME
```
