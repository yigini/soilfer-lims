# Audit 2.3 normalized QC migration

The reviewed installer is `server/scripts/install_qc_runs.js`. It adds four nullable Batch fields, eight normalized tables, fourteen indexes and forty-three guards. It never deletes or rewrites legacy QC JSON, BatchQcResult values, analytical results or AuditLog rows. Legacy fields stay frozen until audit 8.1.

Run it against a quiescent database after installing the earlier audited releases. Take a consistent database and assets backup through the release procedure first. A dry-run opens SQLite read-only and reports the classification, proposed row counts, unresolved metadata, source conflicts and a deterministic fingerprint:

```sh
node server/scripts/install_qc_runs.js --db /absolute/path/lab.db --dry-run
```

Review the counts and every refusal. An import with existing batches requires the exact dry-run fingerprint; the installer reads the plan again under its write lock and refuses if the source has changed:

```sh
node server/scripts/install_qc_runs.js --db /absolute/path/lab.db --apply --plan-sha256 <reviewed-backfillFingerprint>
```

The container entrypoint accepts that reviewed digest as `QC_RUN_PLAN_SHA256`. An existing nonempty legacy installation without its reviewed digest is refused. Direct server startup checks the completed installation read-only before loading the application, writable adapter or scheduler.

The source DDL and the fresh Prisma table oracle are bound to release SHA256 digests. Partial schemas, altered definitions, nonempty unmarked normalized tables and altered receipts are refused. Empty fresh Prisma schemas receive the same partial indexes and guards. An installation receipt is inserted only in the transaction that imports every planned row and installs every guard. A failure rolls the whole transaction back. Repeat installation and the startup check write nothing.

Historical import follows issue #186 scope pins, including part 7. Every snapshot becomes a separate evaluation in sequence order with its own positions and measurements; AuditLog wins over a conflicting Batch.history copy. Current rows are imported last. The original sequence, JSON, typed row, original identifier and values are retained in source/evaluation payloads. Historical positions carry historicalSnapshotSeq and stay outside current sequence and QC views. An empty final clear creates an INCOMPLETE evaluation with LEGACY_CLEARED and no current measurements. It retains all preceding evidence.

Part 8 narrows the non-native freeze to sample membership. Compatibility submissions can append new PROFILE_ONLY QC positions, measurements and evaluations; the latest evaluation identifies that round's current evidence. Native positions stay frozen after first start. Neither path changes historical positions or values.

Evaluated JSON is authoritative. Typed rows supply observations only when JSON is absent or unparseable. Typed/JSON count or value conflicts are reported, and both sources remain intact. Within a snapshot, exact recorded copies may be associated for provenance; UUID ordering never determines the JSON slot order. No association or measurement supersession is inferred between snapshots. Duplicate parent, method, user, instrument, time, number format and catalogue values are never fabricated. Unknown values remain nullable with explicit unresolved counts; recorded censoring has a null measured value and a separate qualifier/limit.

`backfillCount` is the number of inserted normalized rows, including membership, evaluations and events. `backfillCounts` also reports current and historical source quantities, conflicts and unresolved categories. The receipt records these counts and the reviewed fingerprint. It does not signify an audit pass or a deployment. The #162 exact-head Claude audit and post-deployment checks still apply.

This checkpoint supplies the installer, read views, native build/first-start/rebuild services and native measurement/evaluation/correction services. First start re-resolves the complete policy/rule, method LOQ and number format; validates the existing sequence; allocates the ordinal; and freezes those criteria with the authenticated analyst and registered instrument in one transaction. A resumed run reuses its first-start criteria. Shared references resolve every required analyte before any binding write, retain exact value revisions and converted precision, and enforce one physical lot. A shared lot correction re-evaluates affected analytes atomically; flags affect only their results and never change analytical readings.

Part 9 preserves bound QC position ids and all bindings on an unmeasured pre-start rebuild, including extras no longer required. Explicit pre-start lot changes append replacements with `REBUILD_BEFORE_START`. Native OFF runs record `NOT_REQUIRED` on explicit evaluation, with zero fabricated readings; this result is exposed separately from the aggregate acceptance state. Missing ADVISORY evidence is `INCOMPLETE`. A measured extra CRM is evaluated even when its ordinal does not require it.

Part 10 refuses removal of the last member of an analyte with retained reference bindings with `QC_ANALYTE_REMOVAL_BLOCKED`, before any write. An optional lot correction that no longer serves a previously bound analyte appends an explicit `NOT_SERVED` binding with null expected value and snapshot, while superseding and retaining the preceding binding. Required references still require all served analytes. Current evaluation excludes the unserved position; preceding measurements and evaluations remain unchanged.

Part 11 corrects the earlier reopen statement: QC_FAIL remains locked for every role and uses the existing disposition path. No failed-QC reopen route is added. Manager reopen of QC_PASS/QC_WARN records the reason and changes acceptance to QC_PENDING while retaining native measurements and evaluations. Native accepted corrections require this reopen; advisory evidence can be corrected without one. Compatibility reopen hides the old round from the current view, preserves it as evidence, and the next ordinary full submission appends new PROFILE_ONLY positions, measurements and an evaluation with its REOPENED event id. The deprecated JSON and BatchQcResult rows stay unchanged.

Part 12 freezes explicit `requiredPositions` by kind and analyte in first-start criteria. Counted kinds use their first required slots in sequence order; calibration uses opening/closing checks and the first pair at each analyte boundary. Other served slots are optional, so positive-minimum extras can become NOT_SERVED without dropping required service. Compatibility ordinary resubmission may supersede a changed real SAMPLE parent measurement once, with `LEGACY_RESUBMISSION` and the round's reopen id recorded in immutable source metadata. The new DUP remains linked to that same SAMPLE. An unchanged raw/canonical parent reading is reused; historical unresolved pairs stay unchanged.

The retained create/read/update/evaluate routes now use normalized views and one shared mutation transaction. The Native collection adapter requires physical position ids, stores duplicate readings on their actual SAMPLE/DUP parents, and checks supplied expected values against immutable full-precision placements. Status or metadata refusals roll back every observation, evaluation, flag and event. Authenticated HTTP contracts cover Native build/start/entry/reopen/correction and retained compatibility pass/reopen/resubmission cycles, including technician reopen refusal. Native API criteria and number formats use their first-start snapshot even after live policy changes.

Part 13 permits a null instrument on Native OPEN runs and on non-calibration first start. A profile run with recorded methods converts to Native while keeping its free-text name. Calibration verification requires an active asset in the run's laboratory at first start; invalid or foreign assets are refused with 422 and zero writes. Each first-start snapshot records the exact instrument id and text. Later instrument-id changes are refused.

Membership routes now rebuild Native sequences before first start, and retain the unresolved profile flow with real SAMPLE/work-item joins, explicit rack positions, reserved slots and capacity refusals. Started, measured and legacy-frozen membership remains locked after reopen. The forty-third storage guard also refuses a direct WorkItem insert carrying a frozen batch id. The existing disposition authority appends normalized decisions/events, transitions only the selected analytes' work through the central service, and retains prior failed QC evidence. Deviation acceptance can reach CLOSED without clearing its warning flags or failed evaluation.

Reasoned compatibility corrections use the same correction route and transaction as Native entry. They retain the physical observation key, supersede its current reading once, and append an evaluation selecting the complete latest round. Earlier rounds, snapshots, evaluations and deprecated storage remain intact. Ordinary full resubmission remains available separately. Native OPEN reordering validates the complete proposed order before writes, retains every physical id, join, duplicate parent and lot binding, updates sample rack positions, and records RUN_REORDERED. Started or measured membership cannot be reordered. Reorder previews do not allocate ordinals or freeze criteria.

Native BatchModal now uses real sequence/parent ids, first start, partial observation entry, reasoned corrections, manager reopen and drag reordering. The client remains single-analyte; the server supports independent analytes. Reports and sample/work-item gates project the relevant analyte rather than the run aggregate. OFF evaluations are printed as QC not required (mode OFF), not passing QC. Dashboard unresolved counts read normalized analyte states. Both client and server supply the five locale labels. The asset picker remains deferred to #188.

Part 14 preserves every legacy WorkItem attempt as its own current LEGACY_MIGRATED SAMPLE position and unique work-item join, including SUBMITTED, ACCEPTED, COMPLETED and duplicateOf attempts. Positions follow creation order; recorded rack numbers are kept when compatible with that order, otherwise the next free number is assigned and the original rack remains in source metadata and the diagnostic. No historical snapshot sequence is invented. Each source records workItemId, workItemStatusAtImport and duplicateOfWorkItemId. The dry run reports multiAttemptMembershipGroups; the three-attempt contract reports one group and three positions/joins with all original rows unchanged. Cross-lab membership remains a refusal. Native builds refuse a second active sample/analyte membership with 422 QC_BATCH_DUPLICATE_MEMBERSHIP and zero writes, and retain the sealed-work refusal for ACCEPTED history.

Part 15 resolves reporting modes once through the existing qcModes hook. Started Native analytes use their first-start criteriaSnapshot.qcMode, including after reopen; compatibility, migrated and unstarted runs keep live policy. Linked result/work-item batches contribute modes and the strictest wins: REQUIRED_BLOCKING, REQUIRED_WARN, ADVISORY, OFF. Report evidence and refused publication responses include the result id, effective mode, source and contributing batch ids, plus each contribution's analysis/mode/source. The source describes a winning contribution, preferring FROZEN on a tie. Malformed frozen modes return 409 QC_POLICY_UNRESOLVED without a live-policy fallback. Texture fractions resolve through their governing PSA/texture work, and Native flags affect those derived results without touching other analytes or values.

Part 16 maps the reviewed historical REJECT_REANALYSIS label to a REPEAT_BATCH disposition. Its analyte state follows the existing legacy batch-state mapping, including REPEAT_ORDERED for QC_FAIL. Import never starts a repeat run or changes WorkItems. ACCEPT requires passing imported evaluations and becomes an opaque LEGACY_DISPOSITION event, with its original reason; it creates no canonical disposition or deviation flag. The current analyte state follows the passing evaluation, preserving CLOSED when recorded. ACCEPT on failed or incomplete evidence and other unreviewed labels refuse with QC_LEGACY_DISPOSITION_UNRESOLVED. The dry run reports legacyDispositionMapped.REJECT_REANALYSIS and legacyDispositionMapped.ACCEPT_OPAQUE.

Part 17 records explicit provenance for these two labels. A matching AuditLog record is authoritative; the unchanged field copy stays in payload and disagreement is counted as DISPOSITION_ATTRIBUTION_CONFLICT. With no audit record, the original Batch.disposition bytes, by and at supply BATCH_DISPOSITION_FIELD attribution, with null auditLogId and seq. Raw actor text is retained; actorUsername resolves only an exact existing username, and no user is created. Missing or unparseable time stays in the payload while the event time is null. Snapshot replacement actors/times never become original decision provenance. Unresolved or ambiguous audit evidence refuses. The dry run reports dispositionAttribution.AUDIT_LOG, dispositionAttribution.BATCH_DISPOSITION_FIELD and dispositionAttributionConflicts. The installed receipt validates both grouped count objects and the existing flat counts as nonnegative integers; malformed counts refuse startup and repeat installation.
